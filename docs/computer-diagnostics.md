# Computer diagnostics (optional)

The computer diagnostics page is a separate, read-only evidence source. It never infers an electrical fault from CPU, disk, process, port, service, or development-tool data. Its eight simulator scenarios work without a local collector or ReWeird hardware.

`GET /api/v1/computer/scenarios` lists simulated cases. `POST /api/v1/computer/simulate` accepts `{ "scenario_id": "PORT_CONFLICT" }` and returns a versioned snapshot, explicit expectations, deterministic findings, and separate `physical_evidence`, `computer_evidence`, and `software_evidence` arrays. Other scenarios cover healthy resources, high memory, high disk, a stopped expected service, an unreachable localhost service, a missing dependency, and a version mismatch.

Real collection is off by default. On a trusted local Windows backend, set `COMPUTER_DIAGNOSTICS_ENABLED=true` and explicitly click *Collect read-only snapshot* in the UI. The endpoint rejects non-loopback callers even if the backend listens on a wider interface. The fixed Windows inventory command collects OS and resource usage, bounded disk/process/listening-port/interface/service metadata, and availability of a small tool allowlist. It does not read command lines, environment variables, logs, security databases, file contents, credentials, or browser data. Its PowerShell invocation has a 25-second timeout; output is bounded to 1 MiB. It never kills a process, changes configuration, starts a service, or runs a command supplied by the client. Expected localhost port checks only connect to `127.0.0.1`.

Rule checks require explicit expectations for a port, service, localhost endpoint, dependency, or exact dependency version. Missing evidence yields an informational finding rather than a claimed failure. The API does not persist computer snapshots yet; they remain in the browser session and are not merged into physical history/reports. This is deliberately conservative until the privacy and consent model for cross-domain storage is designed. The Windows collector is best-effort and has not been hardware-certified. On other operating systems the opt-in collector reports unavailable; simulation still works.
